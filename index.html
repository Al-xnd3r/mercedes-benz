Presentación: Requerimientos de Software

Fundamentos básicos de la Ingeniería de Requisitos

¿Qué es un Requerimiento?

Un requerimiento de software es una condición o capacidad que debe poseer un sistema para satisfacer un contrato, una norma o la necesidad de un usuario. Describe qué debe hacer el software o bajo qué restricciones debe operar.

Elementos de un Requerimiento

  • Entrada (Inputs): Datos que recibe el sistema.
  • Proceso: La lógica o regla de negocio aplicada.
  • Salida (Outputs): El resultado o respuesta generada por el software.
  • Restricciones: Límites tecnológicos, legales o de diseño.

Características de un Requerimiento

Unívoco y Claro

Posee únicamente una interpretación técnica posible.

Verificable

Es posible diseñar una prueba para corroborar su cumplimiento.

Necesario

Cubre una necesidad real del negocio o del usuario.

Tipos de Requerimientos

⚙️ Requerimientos Funcionales (El "Qué")

Definen las acciones, funciones y reglas de negocio que el sistema debe ejecutar al recibir ciertas entradas.

Enfoque: Operaciones directas del usuario.

Ejemplo: El sistema debe permitir al usuario iniciar sesión con su correo y contraseña.

🚀 Requerimientos No Funcionales (El "Cómo")

Establecen las restricciones de calidad, rendimiento, seguridad y condiciones operativas del software.

Enfoque: Desempeño y atributos del sistema.

Ejemplo: La página debe responder a las búsquedas en un tiempo máximo de 2 segundos.

Ejemplos de Requerimientos

Ejemplo 1: Requerimiento Funcional

Descripción: "El sistema debe permitir a los usuarios autenticarse ingresando su correo electrónico y contraseña, enviando un código OTP de validación de 6 dígitos al correo registrado antes de conceder acceso."

Ejemplo 2: Requerimiento No Funcional

Descripción: "La plataforma debe procesar y desplegar el resultado de una búsqueda en un tiempo de respuesta máximo de 2 segundos cuando haya hasta 1,000 usuarios concurrentes."
